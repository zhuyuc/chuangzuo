中文排版调研与龙吟优化方案

调研 GitHub 上成熟的中文排版项目，拆解它们如何处理首行缩进、标点、中西文混排、行高与阅读宽度，并给出一套适合龙吟“长篇写作 + 本地优先”的单一落地方案。

调研日期：2026-11-02 范围：Heti、typo.css、Han.css、pangu.js、中文文案排版指北、W3C CLReq 结论：内容与版式分离，版式由 CSS 承担

01 · 结论先行

成熟项目没有把“首行缩进”写进正文内容，而是把中文排版拆成三层：

内容层

作者写的是干净文本：段落、标点、换行。中英文之间是否加空格、是否首行缩进，不进入正文主副本。

版式层

用段落元素 <p> 和 CSS 完成 text-indent:2em、行高、字距、两端对齐、避头尾与阅读宽度。

增强层

浏览器暂不支持的标点挤压、中西文自动间距，才由 JavaScript 在渲染层补充，并且不写回正文。

给龙吟的唯一建议：正文继续保存干净文本；新增“排版预览/阅读视图”，由 CSS 负责首行缩进与阅读节奏；“中文排版”按钮不再向正文插入 U+3000，只保留标点与空行校正，缩进只在预览和导出时生成。

03 · 源码级拆解

3.1 Heti：CSS 打底，JavaScript 只补浏览器缺口

Heti 的 CSS 负责正文的阅读节奏。它的段落默认不是“缩进”，而是段间留白加两端对齐；只有古文、行间注、多栏等书籍式版式才打开 text-indent:2em。

.heti p {
  margin-block-start: 12px;
  margin-block-end: 24px;
  text-align: justify;
}

.heti--ancient p,
.heti--annotation p {
  text-indent: 2em;
}

.heti {
  letter-spacing: .02em;
  line-break: strict;
  text-spacing-trim: normal;
}

当 text-autospace、标点挤压等 CSS 特性支持不完整时，Heti 用约 9.7KB 的增强脚本，在渲染层插入 <heti-spacing> 标记：

const heti = new Heti('.heti');
heti.autoSpacing();
// 在 CJK 与拉丁字母/数字边界插入间距标记
// 对连续全角标点做挤压
// 不修改正文原始字符串

它还把 pre、code、sup、sub 等非正文元素排除在自动间距之外，避免把代码和公式排坏。这是“排版增强不碰内容”的典型做法。

3.2 typo.css：把现代 CSS 用到极致

typo.css 用纯 CSS 完成大部分中文阅读规则，核心组合如下：

.typo {
  font-family: var(--typo-font-serif);
  line-height: 1.75;
  line-break: strict;
  word-break: normal;
  overflow-wrap: break-word;
  hanging-punctuation: allow-end;
  text-autospace: ideograph-alpha ideograph-numeric;
  text-spacing-trim: normal;
  text-emphasis-position: under right;
}

.typo-readable { max-width: 48em; }

.typo-justify {
  text-align: justify;
  text-justify: inter-character;
}

.typo-vertical {
  writing-mode: vertical-rl;
  text-orientation: mixed;
  line-height: 1.8;
}

它同时提供简繁两套字体栈：正文用宋体/思源宋体，标题用黑体/思源黑体，楷体和仿宋作为显式 helper。这个“正文宋、标题黑、特殊场景楷/仿宋”的分工，比全站单一字体更接近纸书。

3.3 Han.css：规则最全，但体量也最大

Han.css 约 64KB，包含 normalize、汉字标点、着重号、Ruby/注音、直排和大量兼容选择器。它证明了中文排版可以完全由 CSS 承担，但也说明“把所有规则一次性塞进一个框架”会带来较高的样式复杂度和覆盖风险。对龙吟来说，更适合按需摘取规则，而不是整体引入。

3.4 pangu.js：自动空格的边界处理

pangu.js 的核心不是简单替换，而是判断“边界”是否真的需要空格：

needsBoundarySpace(currentTail, nextFirst)
spaceJunction(currentTail, nextFirst)
isQuoteNextToCjk(last, first)
isStandaloneQuote(text)

它会区分 CJK、拉丁字母、数字、标点与引号，避免在引号、HTML 标签和代码块中误加空格。但它的输出是插入空格字符，因此更适合“阅读器渲染网页”而不是“写作工具修改正文”。

3.5 中文文案排版指北与 W3C CLReq

两者提供规则依据，而不是代码：

  • 中文与英文、数字之间应有可感知的间距；全角标点与其他字符之间不再加空格。
  • 使用全角标点；避免重复标点；专有名词保持正确大小写。
  • 行首禁则：句号、逗号、顿号、分号、冒号、问号、叹号、右引号、右括号不能出现在行首。
  • 行尾禁则：左引号、左括号不能出现在行尾。
  • 连续全角标点可挤压；句末标点可悬挂；中文正文首行缩进两个字符。
  • 直排使用 writing-mode: vertical-rl，Ruby 使用 ruby-position。

04 · 共性结论

  1. 内容与版式分离。成熟项目不会把首行缩进、半角转全角、自动空格写进正文主副本；这些都属于展示层或导出层。
  2. 段落模型是前提。首行缩进必须作用在段落元素上。纯 <textarea> 只有一个文本流，无法给“每一段”加 CSS 缩进。
  3. CSS 优先，JavaScript 兜底。行高、字距、宽度、两端对齐、避头尾、着重号都能用 CSS；只有浏览器未普及的标点挤压和中西文间距才用脚本。
  4. 阅读宽度比字号更重要。正文不是越宽越好；成熟方案普遍把阅读列控制在 34–48em，配合 1.7–2.0 行高。
  5. 规则要可降级。text-autospace、text-spacing-trim、hanging-punctuation 的支持度并不一致，必须用 @supports 渐进增强，不能牺牲基本可读性。

05 · 龙吟现状审计

5.1 当前“中文排版”做了什么

当前实现位于 web/js/domain/writing/format.js，点击按钮后直接修改正文：

// 1. 中文后的半角标点转全角
// 2. ... 转 ……，-- 转 ——
// 3. 删除行尾空格，压缩连续空行
// 4. 每个非空行前插入两个全角空格
// 5. 已是 　　 的行、# 标题、> 引用、- / * 列表跳过

它把“内容规范化”和“版式呈现”混在一次操作里，而且直接写入正文。

5.2 已暴露的问题

问题原因影响
第一行不缩进末尾 .trim() 删掉了整篇首部空白，包括刚加上的 U+3000已修复 但说明“改正文”很脆弱
正文被装饰字符污染缩进写入正文，而不是由版式生成AI 上下文、搜索、字数、复制、导出都带着不可见空格
每个非空行都被当成一段按换行逐行缩进硬换行的续行也会被缩进，段落语义被误判
无法做真正的段落排版编辑器是 textarea，没有段落元素行高、首行缩进、两端对齐只能作用于整个文本流
阅读行宽偏长编辑区正文列 960px，17px 字号约 56 个汉字/行长段落阅读时回行困难，眼睛容易串行

5.3 现有优点

  • 正文已经使用宋体优先的 --font-reading 字体栈，方向正确。
  • 行高 2.12、17px 字号，基础阅读节奏不差。
  • 暗色模式与专注模式已具备，版式层可以复用。
  • 正文主副本是 Markdown 纯文本，天然适合“内容与版式分离”。

现状：内容里塞缩进

　　第一段被写入了两个全角空格，复制、搜索和 AI 上下文都会带着它。第二段同样如此，硬换行的续行也会被误缩进。

缩进是内容的一部分，删除按钮也删不掉语义。

建议：内容干净，CSS 缩进

第一段保持干净文本，首行缩进由 text-indent:2em 产生。复制、搜索、AI 上下文都只看到真正的文字。

第二段同理。行宽、行高、两端对齐、避头尾由阅读视图统一控制。

06 · 优化方案

方案名称：内容与版式分离 + 排版预览。只做这一套，不引入第二套并行的写法。

01 · 正文干净 Markdown 纯文本，不写入装饰性空格
02 · 解析按空行/非空行解析为段落，保留标题、引用、列表
03 · 版式阅读视图用 <p> + CSS 完成缩进、行高、对齐、避头尾
04 · 导出按需在导出边界添加缩进，正文主副本不变

6.1 数据层：正文保持干净

  • 正文主副本继续是每章一个 .md 文件，不写入 U+3000。
  • 段落定义：连续非空行视为一个段落；空行分隔段落；#、>、- 、* 保留结构语义。
  • 标点校正只做“半角转全角、省略号、破折号、压缩空行”，不再插入缩进。
  • AI 上下文、搜索、字数、复制、备份都使用干净正文。

6.2 版式层：新增阅读视图

在写作页工具栏把“中文排版”改为“排版预览”，打开只读阅读视图。正文按段落渲染为 <p>，由统一类名 .chapter-prose 接管版式：

.chapter-prose {
  max-width: 38em;
  margin: 0 auto;
  font-family: var(--font-reading);
  font-size: 17px;
  line-height: 1.95;
  letter-spacing: .01em;
  text-align: justify;
  text-justify: inter-character;
  line-break: strict;
  word-break: normal;
  overflow-wrap: break-word;
  hanging-punctuation: allow-end;
  text-autospace: ideograph-alpha ideograph-numeric;
  text-spacing-trim: normal;
}

.chapter-prose p {
  margin: 0;
  text-indent: 2em;
}

.chapter-prose h1,
.chapter-prose h2,
.chapter-prose blockquote,
.chapter-prose li {
  text-indent: 0;
}
  • 阅读宽度：38em 约 646px，17px 宋体约 38 个汉字/行，接近纸书阅读节奏。
  • 首行缩进：只作用于 p；标题、引用、列表不缩进。
  • 两端对齐：text-align: justify + text-justify: inter-character；不支持时退化为左对齐，不强行拉伸。
  • 避头尾：line-break: strict、word-break: normal、overflow-wrap: break-word。
  • 渐进增强：text-autospace、text-spacing-trim、hanging-punctuation 用 @supports 包裹；不支持时保持普通排版，不做 DOM 注入。
  • 字体：正文继续 --font-reading（Noto Serif SC / Source Han Serif SC / Songti SC）；标题用现有展示字体，不混用。

6.3 交互层：一个入口，三个明确动作

工具栏“中文排版”改为“排版”入口，打开预览面板。面板里只保留三个动作，避免把不同语义混在一次点击里：

  1. 预览：默认展示当前章的排版效果，不写入正文。
  2. 标点校正：只处理标点、省略号、破折号和空行，应用前展示差异，可撤销。
  3. 复制排版文本：复制时临时给每段加 U+3000，用于外部编辑器或粘贴到不支持 CSS 的地方；正文主副本不变。

这样“首行缩进”从一次不可逆的内容修改，变成可预览、可撤销、可选择的输出。

6.5 兼容与边界

  • 不引入 contenteditable 富文本编辑器；现有 textarea 的撤销、@ 选择器、输入法行为保持稳定。
  • 不在编辑器中自动插入中英文空格；需要时在阅读视图用 CSS 渐进增强。
  • 不把 Han.css 整体引入；只摘取与正文阅读相关的规则，避免 64KB 样式覆盖现有视觉系统。
  • 诗词、引用、列表、代码块、英文段落单独豁免缩进与两端对齐。
  • 导出 Markdown 默认保持干净文本；需要“带缩进 txt”时走导出边界，不污染主副本。

6.6 收益与代价

收益

  • 正文可复制、可搜索、可被 AI 正确理解。
  • 首行缩进、行宽、行高可以随时调整，不需要改历史正文。
  • 排版错误可一键回退，不再依赖撤销栈。
  • 阅读视图可以独立优化，不影响写作编辑器。

代价

  • 需要新增一个预览界面和一套排版样式。
  • 编辑器本身仍然不显示段落缩进，作者看到的是干净稿纸。
  • 部分高级特性（标点挤压、悬挂标点）依赖浏览器支持，需接受渐进降级。

07 · 验收标准

  • 正文主副本中不出现由预览产生的 U+3000；保存前后文本哈希一致。
  • 阅读视图中第一段首行缩进恒为 2em，标题、引用、列表不缩进。
  • 阅读列宽度为 38em，行高 1.95，字号 17px，全部来自 token。
  • “标点校正”只修改标点、省略号、破折号和空行，不修改缩进。
  • “复制排版文本”复制出的内容带 U+3000，但正文主副本不变。
  • 不支持 text-autospace 的浏览器仍保持可读，不出现重叠或溢出。
  • 门禁覆盖：段落切分、标点校正、导出缩进、首行缩进 CSS、正文不含装饰空格。
