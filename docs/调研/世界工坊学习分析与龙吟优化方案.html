世界工坊学习分析与龙吟优化方案

拆解《世界工坊 v1.28》的产品结构、数据模型、写作链路和本地存储实现，判断哪些方法值得龙吟吸收，哪些能力应当明确不学，并给出一版可执行的优化方案。

分析对象：世界工坊 v1.28 桌面版资料：源码、存档 JSON、服务端、界面截图对照：龙吟当前交互原型

01 结论先行

最值得学的是数据模型

世界工坊用一套“实体＋类型字段＋通用关系”管理角色、地点、势力、物品、事件和规则，页面只是数据的不同视图。

它的设定字段在服务故事

人物必须回答动机，规则必须写代价，物品必须写力量与成本，角色秘密还记录谁知道、谁在怀疑。

它把创作完整性做成了产品能力

孤立条目、必填缺失、关系断裂、重名、规则冲突都可以被检查并跳转处理，而不是只靠作者记忆。

不要复制它的全部体量

十四个导航视图、程序化地图、灵感投掷、命理和单用户无鉴权架构，不适合直接搬进龙吟。

对龙吟的总建议

吸收“统一实体、关系语义、设定约束、写作辅助、本地可靠性”，不吸收“大而全的世界模拟器和单机架构”。龙吟仍应围绕长篇写作，不把自己变成世界工坊的复制品。

02 项目事实与结构

世界工坊是一个 Electron 桌面应用，界面本身是本地网页，由内置 Node 服务提供静态页面与文件读写。它不是在线 SaaS，也没有账号体系，所有内容围绕单个世界目录展开。

维度实际实现对龙吟的判断
应用形态Electron 外框＋本地 Node 服务＋原生 HTML/CSS/JS；服务只监听 127.0.0.1。本地可靠性值得学；网络与账户模型不能照搬。
世界结构一个世界一个 JSON；存档、素材、稿件、导出、数据分区保存。文件可读、可搬移值得学；龙吟需要账户隔离与更细的版本粒度。
实体类型世界、地区、势力、角色、种族、器物、事件、规则，共 8 类；每类有独立字段模板。类型化字段值得吸收；龙吟不需要第一版上齐八类。
关系模型关系可连接任意实体，含类型、备注、强度；支持力导向关系网与中心展开思维导图。跨类型关系很值得学；龙吟还要保留剧情阶段与作品归属。
叙事结构书有全书大纲，卷有卷大纲，章有标题、状态和正文。示例数据还保存了章节视角、目标、冲突、结果和字数。“大纲分层、章保持轻量”值得借鉴，但不强制所有章填满卡片。
写作三栏写作：结构树、正文、工具；自动保存到世界 JSON，同时写入独立 Markdown 文件。多格式保存值得参考；龙吟应避免正文双份存储产生冲突。
地图程序化大陆、七种地形笔刷、等高线、河流、导入图片、图钉绑定实体、PNG 导出。图钉与实体关联值得学；程序化地图不应成为龙吟研发重点。
完整性检查断链、重名、必填缺失、孤立条目、规则状态和事件年份，并支持 AI 检查。确定性的一致性检查应进入龙吟。
交互Ctrl+K 命令面板、撤销重做、快捷键、皮肤、专注写作、自动中文校正。命令行搜索与写作效率工具值得选择性吸收。
账户与安全无登录、无账户、无跨设备同步；服务假设只在本机回环地址使用。不能直接用于龙吟的“账户＋本地服务器＋外网访问”。

03 值得龙吟学习的能力

3.1 统一实体模型，而不是六套互不相干的数据

世界工坊把角色、地点、势力、物品、事件和规则统一成“实体”。它们共享名称、摘要、标签、正文、图片和关系，又各自拥有专属字段。实体库只是这些数据的筛选视图，关系网和地图是另外两种视图。

对龙吟的价值：当前人物、物品、地点各有一套结构，跨类型关联能力弱。应该建立统一实体内核，让“人物关系”“地图”“物品与武器”成为同一数据体系的不同投影，而不是各存一份。

落地原则

不要让用户先理解“实体系统”。保留现有六个创作入口，只在底层统一对象、ID、关系、标签、附件和搜索。

3.2 类型化字段，而不是所有对象都只有名称和备注

世界工坊的字段有明确的写作目的：角色填身份、阵营、动机、秘密、能力和限制；势力填目标、资源、软肋；器物填持有者、来源、力量、代价；规则填法则、代价、例外和状态。输入框里的提示语也在帮助作者思考。

对龙吟的价值：当前物品字段已经比旧版完整，但人物字段仍偏少。应把“作者需要填写什么”做成模板，而不是让用户面对空白备注框。

实体建议字段建议必填/提醒
人物姓名、别名、身份、阵营、年龄、当前位置、动机、弱点、能力、能力代价、秘密、标签、人物笔记动机建议提醒，但不硬阻断保存
地点名称、父级地点、地貌、气候、控制势力、危险、地图坐标、关联章节父级地点与地貌
势力名称、类型、领袖、目标、资源、软肋、关联人物与地点目标
物品/武器名称、分类、具体类型、持有者、来源、能力、代价、当前状态、首次出场能力与代价

素材标题、来源链接、附件、标签、摘录、笔记、引用章节来源或附件至少一项

3.3 角色秘密：让设定直接制造剧情张力

世界工坊的角色秘密包含是否存在、是否公开、威胁程度、秘密内容、知情者与怀疑者。它把“人物档案”变成了剧情工具，作者不只知道人物是什么，还知道谁掌握信息、谁在猜。

对龙吟的价值：这是高性价比差异点。建议在人物抽屉中新增“秘密”区，秘密必须绑定人物和知情/怀疑对象，并能在写作侧栏提示“本章涉及秘密的人”。

3.4 一致性检查：从资料存储升级为创作校验

世界工坊可自动发现关系断链、重名、必填字段缺失、孤立条目、状态为“存疑/冲突”的规则、缺少年份的事件。每条提示都能跳转到对应条目。

对龙吟的价值：无需 AI 就能实现。龙吟可以检查：关系端点缺失、人物重名、章节引用了不存在的对象、物品持有者不存在、地图地点无人关联、共享库来源丢失、人物秘密的知情者无效。检查结果应显示在作品工作台，而不是埋在技术页面。

3.5 统一的编辑抽屉

世界工坊从任何视图打开实体时，都使用同一个详情抽屉：类型、名称、摘要、专属字段、标签、图片、秘密、Markdown 正文、关联和时间信息。这样列表、地图、关系图都只负责“找到人”，编辑体验只有一套。

对龙吟的价值：当前不同模块各有独立弹窗，字段和交互不统一。应抽象一个实体编辑器，各模块只控制打开哪个实体、显示哪些额外面板。

3.6 写作链路中的作者效率工具

  • 书/卷大纲始终可参照：避免写作时只看到单章卡片。
  • 正文自动保存到 Markdown：数据格式可迁移，退出前有保存状态。
  • 中文自动校正：半角标点、省略号、引号、空行和段首缩进。
  • 专注模式与字数/速度：减少干扰并提供写作反馈。
  • 章节状态：写作中 / 待修 / 完成，颜色清楚。

对龙吟的建议：优先吸收“书卷大纲参照、中文标点校正、状态和保存状态”；同义词库、稿纸皮肤、标点面板属于后续增强，不应抢主流程。

3.7 全局搜索和命令面板

世界工坊提供 Ctrl+K 命令面板，可搜索实体，也可执行“新建角色、打开导出、随机灵感”等动作。关系图、实体库和写作树都能从这里快速跳转。

对龙吟的价值：长篇作品内容量大，逐页找资料会打断写作。建议实现“搜索人物/地点/物品/素材/章节＋执行新建/打开导出”的统一入口，但不恢复已被移除的顶部账户栏。

3.8 本地数据可靠性

世界工坊服务端采用临时文件写入后原子重命名，素材按内容哈希存放为独立文件；存档、素材、稿件和导出分区；导出 JSON 可迁移，浏览器存储作为服务不可用时的回退。这些都是成熟做法。

对龙吟的价值：龙吟必须优先落地真实持久化。当前原型仍是页面内存数据，与“本地服务器保存”的产品承诺不一致。应吸收原子写入、素材文件化、完整备份与恢复，并补上账户隔离和鉴权。

04 不应照搬的设计

世界工坊做法为什么不直接搬到龙吟龙吟应采用
十四个并列导航把创作、世界观、灵感、命理、档案和设置放在同等层级，作者需要先学习产品结构。保持当前三组六入口；辅助能力放进搜索、抽屉或上下文操作。
程序化地形生成与笔刷代码量高、维护成本高，和“小说写作”主目标距离较远。底图上传、地点图钉、图层、拖动与章节关联。
单世界一个大 JSON不利于账户共享、跨作品引用、细粒度版本和冲突处理；地图网格和正文会放大文件。账户目录＋作品目录＋实体/章节独立文件＋索引；正文 Markdown。
无登录、只监听回环地址与龙吟必须账户登录、数据跟账户走、支持外网访问冲突；现有接口没有面向公网的鉴权和防滥用设计。账户隔离、会话鉴权、权限校验、CSRF/限流、TLS、审计与备份。
内存中的撤销栈撤销只在当前运行期有效，重启后无法恢复；完整世界快照对长篇数据也较重。操作日志＋章节持久历史＋可恢复快照，区分短期撤销与长期版本。
正文同时存 JSON 和 Markdown双份正文有同步风险，哪一份是真相不清晰。Markdown 为正本，索引只记录路径与摘要，避免双写。
AI、命理、随机世界、文本拆解会稀释龙吟的写作工具定位，也增加模型、隐私和解释成本。暂不作为核心；未来只做可选的连续性辅助。
皮肤、同义词库、标点库对特定作者有价值，但不是当前转化和留存的关键断点。先完成可靠写作闭环，再按使用数据补充。

06 建议的数据与字段模型

6.1 实体模型

不要求第一版就实现八种类型。先建立统一实体，再把现有类型映射进去；新增“势力”“规则”“事件”时不需要再重做一次数据结构。

6.3 字段呈现原则

  • 固定区域：名称、摘要、专属字段、标签、附件、关系、Markdown 笔记。
  • 按需展开：秘密、高级字段和元数据不占据第一屏。
  • 输入即提示：占位文字承担创作提问，例如“这个人物真正想要什么”。
  • 软性校验：名称等身份字段可硬性要求；动机、代价等叙事字段用提醒而非阻止保存，避免卡住初稿作者。

6.4 文件布局

账户根目录/ ├─ account.json ├─ library/ │ └─ entities/{entityId}.json ├─ works/{workId}/ │ ├─ manifest.json 作品元信息、结构版本 │ ├─ entities/{entityId}.json 作品内角色/地点/物品扩展 │ ├─ relations/{relationId}.json │ ├─ outline.json │ ├─ chapters/{chapterId}.md 正文唯一正本 │ ├─ materials/ │ ├─ assets/ 哈希命名，JSON 只保存相对路径 │ ├─ history/{chapterId}/ 持久快照 │ └─ audit/ 最近一致性检查结果（可重建） └─ backups/

写入规则：临时文件写完后原子替换；所有引用使用稳定 ID 和相对路径；删除实体前处理关系、章节引用和地图图钉；索引是可重建缓存，不是数据源。

07 界面布局与字段分布优化

7.1 保持当前六入口，不复制十四入口

龙吟当前侧栏“写作／创作资料／世界设定”三组已经比世界工坊的十四个并列入口更适合小说作者。建议保持，不在首屏增加灵感、命理、拆解、收藏等工具。

统一实体库不一定要成为新导航。可由 Ctrl+K 全局搜索打开“全部实体”视图，并复用当前人物、素材、地点、物品页面作为类型筛选视图。

7.4 可借鉴的视觉与交互细节

  • 实体卡片同时呈现类型、摘要、标签和关系数，帮助作者在列表中判断信息。
  • 空状态不是“暂无数据”，而是告诉作者下一步可以写什么。
  • 关系图提供图例、筛选、缩放到内容和关系标签开关。
  • 图钉删除与实体删除分离，避免地图误删词条。
  • 概览页展示一致性提示，而不是只展示统计数字。
不要学习的形式

世界工坊的页面密度和十四级入口适合“世界构建工具”，不适合“打开就写”的小说工作台。龙吟应保留更少的主入口和更强的写作上下文。

08 写作链路优化

8.1 大纲：书和卷是主结构，章保持轻量

世界工坊明确写着“书有全书大纲，卷有卷大纲；章只负责标题、状态与正文”。龙吟当前三级大纲可在总纲与章节之间保留更细字段，但应避免强制作者为每章填一堆元数据。

建议：保留故事总纲和分卷目标；章节默认显示标题、状态、目标字数和正文入口。章摘要、场景节拍、关联资料保留为“高级规划”可展开项，不抢占主界面。

8.2 写作页：保留专注，补足上下文

  • 右侧当前章文脉保留，并新增“全书/本卷主线”折叠块。
  • 正文自动保存，显示“正在保存/已保存到章节文件”；历史快照独立于撤销。
  • 增加中文标点、空行、段首缩进校正，默认关闭或可撤销。
  • 章节状态和字数目标进入正文头部，不只在设定页面出现。
  • 提供 Ctrl+K 搜索章节、人物、地点、物品、素材与操作，不重新添加顶部冗余账户栏。

8.3 撤销与历史分开

世界工坊用整份世界快照做撤销，简单但只适合短会话，且重启后丢失。龙吟应该采用两种机制：

  • 即时撤销：最近操作的逆操作，用于删错、改错、拖动错误。
  • 持久历史：章节保存版本和关键设定变更，可跨重启恢复。

不要把全作品的完整 JSON 一直放进撤销栈，长篇作品会产生无谓内存和保存压力。

09 实施优先级

P0
真实数据底座
账户隔离的本地服务器持久化；作品/实体/关系/章节文件；原子写入；独立附件；自动保存；备份恢复。先解决当前原型刷新即丢数据的问题。
P0
统一实体与通用关系
人物、地点、物品归入统一实体结构；关系支持任意实体；保留人物关系的剧情阶段与作品归属；现有页面改为实体视图。
P1
字段模板与角色秘密
人物动机/弱点/能力代价；物品能力与代价；地点父子关系；人物秘密的威胁度、公开状态、知情者和怀疑者。必填提示不阻断初稿保存。
P1
一致性检查与全局搜索
检查断链、重名、引用失效、孤立实体、物品持有者、秘密知情者；工作台展示问题数并可跳转。Ctrl+K 搜索全内容与操作。
P1
写作效率增强
书卷主线侧栏、中文标点/缩进校正、章节状态与目标、保存状态、写作字数速度；保持纯文本和专注模式。
P2
地图和共享库深化
地图图钉绑定任意实体、素材文件化、地点父级；共享库引用同步与冲突提示。不做程序化地形和笔刷。
P2
规则与时间线
当作品出现力量体系或复杂历史时，再加入“法则—代价—例外”规则和事件时间线。它们有价值，但不属于当前第一优先级。
不做
世界模拟器型功能
程序化地图、地形笔刷、灵感投掷、命理、皮肤库、文本拆解、AI 生成不作为当前阶段方向。

10 验收标准

  1. 数据真实保存：刷新页面、重启服务后作品、关系、图片、章节和秘密完整存在，并能通过备份恢复。
  2. 实体一致：人物、地点、物品共享同一实体 ID；删除人物后关系、章节引用、物品持有和共享来源都有明确处理。
  3. 关系可用：能建立人物—地点、人物—物品、势力—人物的关系，并按作品和剧情阶段筛选。
  4. 字段有用：作者建立人物时会被提示写动机，建立物品时会看到能力与代价，建立规则时不能只写“无敌”。
  5. 检查可行动：每条一致性提示都能定位到实体或章节；没有断链还显示为正常。
  6. 写作不中断：Ctrl+K、自动保存、撤销、章节历史和中文校正都不会把光标或滚动位置拉回开头。
  7. 安全可外网：账户鉴权、作品越权隔离、上传文件校验、备份恢复和反向代理部署均通过测试；不照搬世界工坊无鉴权的开放接口。
  8. 范围克制：首屏仍只有写作和创作入口；任何新增能力都能说明它如何帮助作者完成正文，而不是单纯增加设定字段。
